# 整体逻辑架构与任务编排

状态：设计基线；具体字段与状态枚举待功能切片验证

## 逻辑结构

```text
桌面界面
  └─ 任务运行时（会话、状态、事件、取消、恢复）
       ├─ 主 Agent / 任务控制器（目标理解、下一步决策、结果综合）
       │    ├─ 上下文与信息服务（文件检索、项目知识、记忆、工作方法）
       │    ├─ 受控工具（文件、分析、写作产物、代码等）
       │    └─ 按需委派的专门 Agent（独立任务、独立结果）
       ├─ Policy / Operation（授权、预览、执行、核对）
       └─ Runtime Store（已提交事实和事件）
```

主 Agent 对最终交付负责；专门 Agent 接收受限目标、输入引用、权限、预算和验收标准，返回结果、证据与产物。信息检索本身通常是工具，不必拟人化为 Agent。

## 单次任务运行

1. 接收用户目标，确定授权工作空间、输入范围及当前约束。
2. 从文件索引与当前会话获取相关信息；需要时再打开原文件核对。
3. 主 Agent 输出一个结构化动作：回答、调用工具、建立/修订计划、委派任务、询问用户或结束。
4. 运行时代码校验动作、权限、预算和状态；执行后持久化结果，再进入下一步。
5. 需要修改或发布时，先形成明确的变更内容与目标，检查文件版本；根据操作规则展示预览并接收用户决定。
6. 汇总完成程度、来源、产物、实际操作和未完成项，提交最终结果。

## 编排策略

- **默认直接执行**：定位文件、读取和简单总结不进入 Planner。
- **按需轻量计划**：多阶段依赖、较大批量、跨文件分析或需要预览执行范围时建立计划。计划可随新事实修订，已提交结果不能被悄悄改写。
- **按需委派**：独立且可验收、需要不同工具或较长上下文的子任务适合专门 Agent。子 Agent 不自行扩大授权，也不与其他 Agent 自由交换未提交状态。
- **并行作为优化**：先验证串行语义；只有独立任务有实际收益时才引入并行调度、资源互斥和 join 策略。
- **受控结束**：步骤、时间和成本有限额；没有新增事实的重复动作须停止并报告部分结果或阻塞原因。

## 核心契约

| 契约 | 最少需要表达 |
|---|---|
| Task | 用户目标、输入范围、成功标准、约束、预算 |
| Action | 动作类型、目标、参数、所依赖的已提交引用 |
| Result | 完成程度、证据、产物、错误与未完成项 |
| SourceReference | 文件身份、内容版本、位置、解析来源 |
| Operation | 规范参数、风险、预览、授权决定、执行与核对状态 |
| RuntimeEvent | 用户可见进度和诊断所需的状态变化 |

字段、数据库表和 Graph 节点以纵向功能验证为准，不预先要求完整通用 DAG。状态生命周期与结果质量分别表示；无法确认外部副作用时进入待核对状态，不自动重复写操作。

## 能力扩展

文件、写作和代码任务共享同一主运行循环。网页研究增加网络受控工具和来源模型；电脑操作增加屏幕观察、动作范围、关键步骤确认及执行后核对。扩展能力不能直接绕开授权、操作记录与结果验证。
