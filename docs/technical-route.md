# 主要技术路线

状态：设计基线；具体库和模型选择待验证

## 总体原则

采用 **LLM 决策 + 确定性运行时 + 可插拔能力**。模型理解目标、提出下一步行动；代码验证行动、控制生命周期和权限、执行工具并保存事实。模型升级可以改变决策质量，不应改变文件授权与操作语义。

## 技术组成

| 组成 | 方向 | 边界 |
|---|---|---|
| 桌面端 | 桌面界面承载工作空间选择、任务进度、来源、产物和变更预览 | 不直接持有无限制文件或执行权限 |
| 模型网关 | 统一封装本地或远程模型、结构化动作、超时、取消和用量 | 不将模型 SDK 细节渗入任务状态 |
| 任务运行时 | Session/Run、步骤状态、事件、预算、取消与恢复 | 状态转换由代码控制 |
| 文件能力 | 授权目录扫描、元数据、解析、检索、版本检查和文件操作 | 不以模型猜测代替文件身份与内容校验 |
| 计算能力 | 结构化数据分析、代码执行与产物生成逐步引入隔离环境 | 产物先生成和验证，再选择发布位置 |
| 数据持久化 | SQLite 保存运行事实、配置与索引元数据；大内容和产物独立保存 | 原始事实、文件索引、长期记忆分开 |
| 权限控制 | 工作空间范围、工具能力、操作风险和用户决定取交集 | 模型或 Skill 不能扩大授权 |

现有 V2 文档选择 Electron/React + Python + SQLite，可作为实现起点；宿主和库的具体选择在项目骨架阶段结合打包、启动和本地模型需求验证，而不是由旧 ADR 自动决定。

## 信息体系

1. **运行事实**：消息、任务、步骤、工具调用、授权决定和产物，供恢复与审计。
2. **文件索引/项目知识**：文件身份、路径、版本、解析内容和出处；增量更新，检索结果可回到原文件位置。
3. **长期记忆**：少量稳定的用户偏好与项目约定，可查看、纠正、删除；不得覆盖原始事实或改变权限。
4. **工作上下文**：每次模型调用按目标、权限、来源和 token 预算动态装配；引用已提交信息，不复制全部历史。
5. **工作方法**：可复用的任务步骤和约束，可按需加载，但不能授权工具。

优先提供文件元数据和全文检索；语义检索依据真实查询效果加入。自动长期记忆不作为本地文件闭环的前置条件。

## 演进原则

稳定的是 Task、Action、Result、Operation 和 SourceReference 的语义；可替换的是模型、提示词、检索排序、计划策略与专门 Agent。新增网页或电脑操作能力应作为新的受控执行环境接入，不绕过运行时。
