# 分阶段开发路线图

状态：设计草案；阶段顺序以真实任务验收调整

## 开发原则

每个阶段交付可运行的端到端用户任务，并保留下一阶段需要的稳定契约。不要先实现所有抽象，再等待功能集成。阶段状态在实施时另行记录；本文不表示已有代码完成。

| 阶段 | 用户可完成的任务 | 关键能力与验收 |
|---|---|---|
| P0 产品样例与最小骨架 | 用真实任务样例验证目标和交互 | 选取文件发现、跨文档问答、数据分析、写作、代码、文件整理样例；定义最小 Task/Action/Result；能启动、保存、取消和查看一个任务 |
| P1 本地只读助手 | 在授权目录中找文件、阅读、问答和比较 | 工作空间授权；扫描与元数据/全文检索；基础格式解析；原文定位与版本标记；结果附准确来源 |
| P2 分析与写作 | 分析表格并形成可预览的报告或草稿 | 数据读取、受控统计/绘图、产物生成与预览；以选定资料为依据写作 |
| P3 文件与代码修改 | 修改文件或代码，并检查结果 | 变更清单和 diff、内容版本检查、受控写入、测试执行、结果核对及操作记录 |
| P4 复杂任务编排 | 完成长依赖任务或独立子任务组合 | 按真实案例加入计划修订、委派、并行、共享预算与资源互斥 |
| P5 长期与跨应用能力 | 跨任务复用约定并与其他环境协作 | 可管理的长期记忆；按需扩展网页研究、电脑操作与人机协同 |

## 横向约束

- P0 起保存运行事实、错误与事件；P1 起明确读权限与文件来源；P3 起处理写入预览、版本冲突和副作用未知。
- 每阶段至少验证成功、无结果、取消、错误和重启后的状态；仅对该阶段实际支持的能力建立对应恢复语义。
- 以任务成功率、来源准确性、完成耗时、用户确认负担和错误恢复效果评估设计。
- P4 和 P5 的具体机制依赖 P1–P3 的真实任务记录，不因架构图预留位置就提前实现。

## 下一步

先确定 10–15 个来自真实本地资料的验收任务，为 P1 选取文件类型、规模与引用精度要求，再细化索引、解析和主 Agent 的最小协议。
